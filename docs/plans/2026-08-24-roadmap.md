## 1. L-4: widen the failure taxonomy — retry vs replan vs decompose (MEDIUM)

Today the ladder only handles "the model failed" (retry on the next model). Evidence: CAMEL
Workforce's failure-analysis -> RecoveryDecision pipeline (retry with feedback / replan /
decompose), Magentic-One's progress ledger (re-plan when the team stalls).

Plan:
- Coordinator decision rule in `docs/stages/spawn-fallback.md`:
  1. model/transient error -> existing ladder (unchanged);
  2. task failed QA with the same root cause twice -> replan (PM re-splits the task) or
     decompose (split into smaller tasks) BEFORE the 4-ladder cap is reached;
  3. stall counter on wave-4 -> wave-3 rework loops (already counted in waves.jsonl):
     2 loops -> user-facing checkpoint with a re-plan proposal (the checkpoint rule exists;
     promote it into the fallback section and give it the replan/decompose actions).
- Log the decision in `.pmos/log.md` with the reason; `events.py` already records the runs.
- New fixture: a QA-failed-twice project asserting state.py/coordinator guidance says
  "replan", not "retry ladder again".
- validate.py: fixture wiring.

## 2. L-13: quality-aware model selection (SMALL)

Evidence: Anthropic (token spend predicts output quality -> track quality per model), Roo Code
(sticky per-mode models -> honor the user's last approved choice; already exists as
`~/.jcode/pmos-team-defaults.json`).

Plan:

  table ("historically fails here") rather than silently re-picking it. Recommendation stays
  benchmark-driven; history is a visible flag, not an override (keeps determinism).
- README/EVALUATION.md: document the loop.

## 3. L-10: kill the host lock-in — adapters (STAGED: S -> M -> L)

Evidence: spec-kit runs one process on 30+ hosts by generating host-specific command files;
BMAD ships the same method as skills for multiple tools. PMOS is host-agnostic in spirit but
jcode-locked in practice (swarm spawn / list_models / usage primitives).

Plan:
- Stage S: `HOST-ADAPTER.md` — the contract, precisely: spawn-with-model (label, model,
  effort, prompt), list_models (text file), usage (tokens_in/out per run), session resume.
  Generate a Claude Code subagent set (`.claude/agents/*.md` + commands) from `roster.json`
  so the template RUNS on a second host.
- Stage M: abstract the three primitives behind `tools/host.py` with a jcode backend and a
  MOCK backend; the mock backend doubles as the eval harness's host (contract-tested without
  spending tokens).
- Stage L: a second real backend (Claude Code headless or OpenHands SDK), validated by running
  `eval_project.py` fixtures through it.

## 5. gstack integration (2026-08-24 research: docs/research/2026-08-24-gstack.md)

declarative 10-host adapter system — Hermes included. It composes with PMOS: PMOS is the
protocol layer, gstack skills are execution-layer worker methodology. Integration items,
Ranked by value/effort (details + evidence in the research doc).
