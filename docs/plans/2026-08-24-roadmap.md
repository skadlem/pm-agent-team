## 3. L-10: kill the host lock-in — adapters (STAGED: S -> M -> L)

Evidence: spec-kit runs one process on 30+ hosts by generating host-specific command files;
BMAD ships the same method as skills for multiple tools. PMOS is host-agnostic in spirit but
jcode-locked in practice (swarm spawn / list_models / usage primitives).

Plan:
- Stage S: `HOST-ADAPTER.md` — the contract, precisely: spawn-with-model (label, model,
  effort, prompt), list_models (text file), usage (tokens_in/out per run), session resume.
  Generate a Claude Code subagent set (`.claude/agents/*.md` + commands) from `roster.json`
  so the template RUNS on a second host.
- Stage M: abstract the three primitives behind `tools/host.py` with a jcode backend and a
  MOCK backend; the mock backend doubles as the eval harness's host (contract-tested without
  spending tokens).
- Stage L: a second real backend (Claude Code headless or OpenHands SDK), validated by running
  `eval_project.py` fixtures through it.

  DONE 2026-08-26: the Claude Code headless backend runs the full pipeline live —
  validate.py section 9f spawns a real `claude -p` session, parses usage from the
  result JSON, and records it in the cost ledger (skips when the CLI is absent).
  Two real adapter bugs found and fixed on the way: the spawn command had no
  `<prompt>` slot (claude -p exits 2 without input), and the prompt must follow
  `-p` directly — trailing position gets eaten by the CLI parser. host.py now
  shell-quotes `<prompt>`; hosts/claude.json carries `--output-format json` so the
  result file feeds the usage primitive directly.
