# Research round 2: projects like PMOS (2026-08-26)

**Method:** web sweep for projects NOT covered by the 2026-08-24 survey, READMEs read
directly (raw GitHub), claims below verified against source. Focus: what changed in the
field since the first survey, and what transfers.

## New projects examined

### 1. Ruflo / claude-flow (ruvnet) — 69k stars, npm-distributed swarm runtime
The biggest new entrant. Multi-agent swarms on Claude Code with SQLite+HNSW vector
memory, plugin marketplace, RuVector agentic DB. Notable mechanisms:
- **Thompson-sampling model router**: 3-tier selector (Haiku/Sonnet/Opus) as a
  cost-adjusted multi-armed bandit; `hooks_model-outcome` updates Beta(α,β) priors per
  tier; routes by argmax sample. Self-corrects against tier overuse after ~50 outcomes,
  no manual thresholds. 45µs/route.
- **SONA/ReasoningBank pattern learning** with persistence + seedable PRNG for
  reproducible runs.
- **Self-consistency orchestrator** (`selfConsistency(N, op, agg)`): N samples +
  aggregator for +5–15pp on reasoning tasks at Nx compute.
- Honest engineering hygiene: seedable PRNG "for deterministic tests" is a lesson PMOS
  already follows.

### 2. OpenSpec OPSX (Fission-AI) — 66k stars, spec-driven development
spec-kit competitor whose v2 ("OPSX") is a direct answer to a failure mode PMOS shares:
- **Actions, not phases**: legacy linear workflows ("in planning phase" → "in impl phase")
  fight reality. OPSX: propose/spec/design/tasks/implement/update/archive are actions
  available ANY time, dependencies are enablers not gates.
- **Templates-as-user-files**: instructions live in editable `schema.yaml` +
  `templates/*.md`, not compiled into the package. Edit a template, test instantly —
  "when AI output is bad, you can't tweak the prompts" was their core complaint about
  hardcoded workflows.

### 3. Task Master (eyaltoledano) — 28k stars, task pipeline for AI dev
PRD → tasks.json → per-task files with: id, status, **dependencies**, priority,
`details` (implementation notes), **`testStrategy` field**, subtasks. Plus
`analyze-complexity`: AI scores each task 1–10 and recommends expansion into subtasks
before work starts.

### 4. AWS sample-claude-code-agent-team — official-pattern reference
4 agents (fullstack lead @opus/high, coding @sonnet/high, devops @sonnet/xhigh, review
@opus/xhigh). Two patterns worth noting:
- **Self-claiming shared queue**: implementers pull from a shared task queue instead of
  being assigned.
- **Parallel analysts + single synthesizer verdict**: N review agents review slices in
  parallel; exactly ONE agent owns the final verdict (no verdict-by-committee).

### 5. Ralph (snarktank / ghuntley pattern) — autonomous completion loop
Fresh-context-per-iteration loop: each iteration spawns a NEW agent instance with clean
context, picks highest-priority story where `passes: false`, implements, runs checks,
commits, marks `passes: true`. Memory persists ONLY via git history + progress.txt +
prd.json. Runs until all stories pass or max iterations.

### 6. awesome-harness-engineering — the field's self-description
"Harness engineering = designing context delivery, tool interfaces, planning artifacts,
verification loops, memory, sandboxes around an agent." Key framing: **the best harnesses
are designed knowing their components will become unnecessary as models improve.**

## What changed since the 2026-08-24 survey

1. Spec-driven went mainstream and then immediately loosened: OpenSpec's OPSX explicitly
   rejects rigid phases for action-based workflows — the same direction BMAD v6 took.
2. Model routing moved from static tiers to learned policies (Ruflo's bandit).
3. The "harness engineering" framing crystallized into its own discipline with curated lists.
4. Autonomous loops (Ralph) matured: fresh context per iteration is now the standard
   anti-drift mechanism, with file-based state as the only memory.

## Transferable to PMOS (ranked)

### T1. Actions-not-phases for the protocol (OpenSpec OPSX) — MEDIUM value, MEDIUM effort
PMOS's stage machine (0..9) is deterministic — that's its audit strength — but the roof-bot
dogfood showed real work doesn't respect wave boundaries (rework loops ARE non-linear flow).
Middle path: keep stages as *checkpoints* but let artifacts be updated any time without the
coordinator treating it as an anomaly. Concretely: relax `trace.py unplanned` during waves 2–3
(warn only at checkpoints), and document that plan.md edits mid-wave are normal, not failures.
No machinery change; protocol-text + trace.py severity tweak.

### T2. Complexity analysis before expansion (Task Master) — SMALL effort, real value
Before the PM splits tasks into T-NNN, run a cheap complexity pass: score each planned task
and flag ones needing decomposition. PMOS already has the right place for it (GATE 2 prep)
and the right tool shape (`tools/complexity.py` or a converge.py subcommand). Deterministic
proxy (touches-count, artifact-dependency depth, LOC estimate from graphify) instead of AI
scoring keeps it free.

### T3. testStrategy as a first-class task field (Task Master) — SMALL effort, quality win
PMOS tasks have acceptance criteria A-NNN pointing AT them, but no per-task *how I will
verify* field. Adding an optional `test_strategy:` line to the task template gives reviewers
(QA role) something concrete to check before code exists. Linter change + template change.

### T4. Bandit-style tier routing (Ruflo) — defer
PMOS's recommend.py already does benchmark-driven selection with pass-rate tiebreaks
(shipped today); Ruflo's bandit learns online from outcomes. The idea maps to: adjust
role_tiers or model ladder order from events.py history automatically. Defer until ≥3
real projects produce enough outcomes for learning to beat the benchmarks — same criterion
as the L-2 deferral.

### T5. Fresh-context-per-task enforcement (Ralph) — already implicit; document it
PMOS spawns fresh workers per task by design (stateless spawn primitive). Ralph's lesson is
that this is THE anti-drift mechanism and should be stated as a rule: never resume a failed
worker's session; always fresh instance + artifact handoff. Protocol-text clarification only.

### T6. Parallel analysts + single synthesizer (AWS sample) — SMALL, good for lean QA
For expensive-team QA on big waves: parallel slice reviews are fine, but the verdict must
come from one agent reading all slice reports. One paragraph in wave4.md.

## Not taken

- Ruflo's full substrate (RuVector DB, SONA neural patterns, plugin marketplace): violates
  zero-dependency posture; solves problems PMOS bounds deterministically (caps, excerpts).
- OpenSpec's full fluidity (no stages at all): loses the deterministic audit trail that is
  PMOS's differentiator. T1 takes the middle path deliberately.
- Task Master's AI complexity scoring: costs tokens; deterministic proxy achieves the goal.
